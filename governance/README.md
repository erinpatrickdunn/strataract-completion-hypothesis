# `governance/` — Project Rules and Current Classification

This folder contains the project's own rules for how a result moves
from an idea to a Provisional finding to a Canonical claim — and, just
as importantly, the current classification of every major result in the
project against those rules.

## Why This Exists

Read `SCH_Project_Governance_Charter_v2.md` if you want to know *why*
something is filed where it is, not just *that* it is. The charter
exists because this project has a documented history of results being
migrated into the canonical record before they were actually
independently confirmed — repeatedly, in the same sector of the theory
— and the charter is the specific structural fix for that, not just a
description of it.

The charter defines:

- **Track A / Track B** — the distinction between the settled core of
  the framework and any part currently under active verification.
- **Three status tiers** — Canonical, Provisional, Superseded — and the
  entry bar for each.
- **The Four-Question Rule** — what has to be answered in writing,
  before an edit is made, before any result is allowed to change a
  canonical document.
- **A current classification table** of every major result in the
  project, kept up to date as things resolve.

## On Reading the Charter's Own History

The charter has, at least once, been wrong about its own status — v1
listed a derivation as confirming a result before that derivation had
actually been written down, and v2 corrects this in the open rather
than quietly. This is deliberate: the charter is not exempt from its
own rule. If you're checking whether a claim in this repository is
truly settled, the charter's classification table is the place to look,
but the four-question standard it describes is the actual test — a
classification is only as good as the independent check behind it.

## Version History

Older versions of the charter move to
`superseded/working-superseded/` when a new version replaces them, with
the same discipline as everything else in this project: retained in
full, not edited in place, with the revision note in the new version
explaining exactly what changed and why.
