# Pseudopotential Provenance — Te.rel-pbe-n-rrkjus_psl.1.0.0.UPF

## Category: LITERATURE-VERIFIED METHODOLOGY + DERIVED ARTIFACT

This file is **not** a novel/invented pseudopotential. It was generated by
running the exact, unmodified, established PSLibrary (Dal Corso) generation
recipe for tellurium through `ld1.x`, with the library's own environment
switch (`rel-pbe/environment.job`, i.e. `nrel=2`) that turns the *same*
recipe used for every other PSLibrary element into its fully-relativistic
variant.

## Exact provenance chain

1. **Source repository**: `dalcorso/pslibrary`, GitHub, `master` branch,
   fetched via `codeload.github.com/dalcorso/pslibrary/tar.gz/refs/heads/master`.
2. **Generation recipe location**: `us_ps_low.job`, lines 842–895 (the "low"
   /non-semicore accuracy tier; a semicore "high" tier recipe also exists,
   `us_ps_high.job` lines 1595–1660, and was independently generated and
   passed the same internal atomic test — see `../pseudopotentials/` for
   provenance if that variant is preferred for production use instead).
3. **Environment substitution applied**: `fct='rel-pbe'`, `nrel=2`,
   `gfun='PBE'` — taken verbatim from `pslibrary-master/rel-pbe/environment.job`.
4. **Generator**: `ld1.x`, Quantum ESPRESSO v6.7MaX (as packaged in Ubuntu
   24.04's `quantum-espresso` 6.7-2build4).
5. **Exact input file used**: `Te.rel-pbe-n-rrkjus_psl.1.0.0.in` (included
   in this directory, byte-for-byte what was run).
6. **SHA-256 of the resulting UPF file**: see `CHECKSUM.txt`.

## Validation evidence (two independent, mutually confirming checks)

1. **Generation log** (`generation.log`, included): the internal atomic
   reference calculation explicitly reports **"dirac relativistic
   calculation"**, and the printed atomic levels show real spin-orbit
   splitting — e.g. 5P at *j*=0.5 (−0.47100 Ry) vs. *j*=1.5 (−0.41318 Ry),
   and 4D at *j*=1.5 (−3.10922 Ry) vs. *j*=2.5 (−3.00145 Ry). This is the
   physical signature of spin-orbit coupling being genuinely present in
   the reference calculation the pseudopotential was constructed from —
   not merely a filename or flag claiming so.
2. **UPF header metadata**: the file's own `PP_HEADER` tag states
   `relativistic="full"` explicitly (confirmed by direct inspection,
   independent of the generation log).

## What is NOT independently established

- **Transferability beyond the internal atomic test.** PSLibrary's own
  logarithmic-derivative / plane-wave transferability test suite was not
  run in this environment. This pseudopotential should be treated as
  "generated by the correct, standard recipe and passing its own internal
  consistency check," not as "independently benchmarked against an
  all-electron reference for this specific application" (i.e. Te H-point
  band structure). That benchmark is exactly what Gate 3 (zero-strain
  Delta reproduction) in the package README is designed to provide once
  this package is actually executed.
- **This file could not be read by the locally available Quantum
  ESPRESSO 6.7MaX build** (see `../README.md`, "Known execution
  environment issues" — a reproducible XML parser bug, fully diagnosed,
  unrelated to the pseudopotential's physical validity) **nor by two
  freshly source-built newer QE versions** (6.8, 7.3.1 — both blocked by
  an unrelated hard external dependency, `devicexlib`, hosted exclusively
  on a network host outside this environment's reach). The file has
  **not** been confirmed readable by any working QE installation. Do
  not treat "generated successfully" as equivalent to "confirmed usable
  in a production calculation" — those are the two facts this document
  keeps deliberately separate.

## Do not

- Do not regenerate this file with different parameters "to see if it
  reads better" — if a working QE environment is obtained, use this
  exact file first. Only regenerate if this specific file is
  demonstrated to be physically invalid (not merely unreadable by one
  buggy build).
- Do not substitute the scalar-relativistic GBRV/SSSP Te pseudopotential
  bundled with Ubuntu's `quantum-espresso-data-sssp` package
  (`Te_pbe_v1.uspp.F.UPF`) for this file. That file is explicitly
  scalar-relativistic (confirmed by its own header) and cannot represent
  the H4/H5 splitting at all — this was the original blocker this
  pseudopotential was generated to solve.
